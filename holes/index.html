01 / 05

Ключи в коде страницы

Всё, что лежит в JavaScript страницы, видит любой посетитель. Токен Telegram-бота в коде формы — значит, кто угодно сможет писать от имени вашего бота. Платный API-ключ — тратить ваши деньги.

Проверка за минуту

Откройте свой сайт → F12 → нажмите Ctrl+Shift+F (поиск по всем файлам) и поищите token, key, secret, sk_. Нашли настоящий ключ — это дыра.

Как закрыть

Страница отправляет заявку на свою серверную функцию, а ключ живёт только на сервере, в переменных окружения. Пример функции для Vercel:

// api/lead.js — выполняется на сервере, ключа в браузере нет
export default async function handler(req, res) {
  const { name, phone } = req.body;
  await fetch(`https://api.telegram.org/bot${process.env.TELEGRAM_TOKEN}/sendMessage`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ chat_id: process.env.TELEGRAM_CHAT_ID, text: `Заявка: ${name}, ${phone}` }),
  });
  res.status(200).json({ ok: true });
}

Если ключ уже утёк — отзовите его и выпустите новый. Для Telegram-бота: команда /revoke в @BotFather.

02 / 05

База без защиты

Публичный ключ Supabase в браузере — это нормально, но только если у таблиц включён Row Level Security. Без него база — открытая дверь: в исследовании у 172 сайтов из 1 072 любой мог удалять данные без входа.

Проверка за минуту

Supabase → ваш проект → Table Editor: у каждой таблицы с данными должно быть включено RLS, а в разделе Policies — правила на чтение, добавление, изменение и удаление.

Как закрыть

-- включить защиту таблицы
alter table orders enable row level security;

-- пример правила: человек видит только свои заказы
create policy "свои заказы" on orders
  for select using (auth.uid() = user_id);

И никогда не кладите ключ service_role в код страницы: он обходит все правила.

03 / 05

Пароли в GitHub

Файл .env с ключами уезжает в репозиторий вместе с кодом. Даже если потом его удалить, он остаётся в истории коммитов.

Проверка за минуту

Откройте репозиторий на GitHub и поищите .env. Или в терминале, в папке проекта:

git log --all -- .env

Если команда что-то вывела — файл когда-то был в истории.

Как закрыть

Добавьте в файл .gitignore:

.env
.env.*

Все ключи, которые хоть раз попали в репозиторий, считайте утёкшими и замените на новые. Находить ключи в коде умеет, например, бесплатный инструмент Gitleaks.

04 / 05

Чужой скрипт на сайте

Если текст из формы (отзыв, имя, комментарий) вставляется на страницу через innerHTML, в нём может прийти код, и он выполнится у всех посетителей. Это называется XSS.

Проверка за минуту

Поищите в коде innerHTML, insertAdjacentHTML и dangerouslySetInnerHTML рядом с данными от пользователя.

Как закрыть

// текст остаётся текстом, код не выполнится
review.textContent = form.text.value;

Если HTML действительно нужен — сначала очистите его, например библиотекой DOMPurify: DOMPurify.sanitize(html).

05 / 05

Форма без защиты от ботов

Боты отправляют сотни заявок в минуту: спам в Telegram и почту, а у платных сервисов отправки — счёт.

Как закрыть

1. Скрытое поле-ловушка. Человек его не видит, бот заполняет:

<input type="text" name="company" tabindex="-1" autocomplete="off"
       style="position:absolute; left:-9999px" aria-hidden="true">

На сервере заявку с заполненной ловушкой просто пропускаем:

if (req.body.company) return res.status(200).json({ ok: true }); // это бот

2. Ограничение частоты на сервере: не больше нескольких заявок с одного адреса за минуту.

3. Капча, если спама всё равно много, — например, Cloudflare Turnstile.

Промпт-проверка для Claude Code

Откройте Claude Code в папке сайта и вставьте:

Проверь этот проект на 5 проблем безопасности. Для каждой ответь: есть или нет, где именно (файл и строка) и как исправить.
1. Секретные ключи и токены в коде, который уходит в браузер: API-ключи, токен Telegram-бота, ключ service_role Supabase.
2. Таблицы базы данных без Row Level Security или без правил на чтение, добавление, изменение и удаление.
3. Файлы .env и другие секреты, попавшие в git, в том числе в историю коммитов.
4. Вывод текста от пользователя через innerHTML, insertAdjacentHTML или dangerouslySetInnerHTML без очистки.
5. Формы и API без защиты от спама: нет ограничения частоты, капчи или скрытого поля-ловушки.
Ничего не меняй, пока я не подтвержу план исправлений.
